## Лабораторная работа №3. Отчет

Доброго времени суток уважаемому читателю. На разборе сегодня сборка конпочного приложения Rocket-counter через Redis. 

**Важно!** Все инструкции к выполнению прикрепил в README.md

В ходе работы нашей задачей было изучить принципы работы с Redis, с флагом --link и описать весь стек работы на базе .yml-файла

**Практическая часть**

Запускаем контейнер Redis

```powershell
docker run -d --name redis redis
```

Контейнер запустится, после чего мы спокойно сможем работать с приложением. Возникнет лишь одна проблема - образа с приложением rocket-counter нет в базах Docker. На такой случай для Вас я закреплю папку с этим приложением. В ней есть compose.yml (чуть позже расскажу, как с этим будем работать). Название папки - **/rocket-counter-main**

Переходим в папку

```powershell
cd /rocket-counter-main
```

и запускаем сборку

```powershell
docker build -t rocketcounter:latest .
```

Отлично! Все собралось, значит, можно проверять. Базово (как и было прописано изначально в файле сборки) образ можно запустить с порта 8085:5000, это прописано в строке 

```yaml
rocketcounter:
    build: .
    ports:
    - 8085:5000 # -> вот тут
```

Запускаем 

```powershell
docker run -d --name rocketcounter -p 8085:5000 --link redis:redis rocketcounter:latest
```

На http://localhost:8085 все должно заработать

После этого останавливаем оба контейнера (второй, с rocket-counter придется удалить)

```powershell
docker stop redis
docker compose down -v # -> эту команду я принципиально запускал из папки
```

И вот теперь можно сделать несколько копий. Заходим в compose.yml и меняем строку

```yaml
rocketcounter:
    build: .
    ports:
    - :5000 # -> вот тут
```

Можно конечно написать и ''0:5000'', но я как-то оставил пустым, потому что это не сыграло роли. Docker подхватывает порты автоматически, если не прописывать самостоятельно

Снова собираем

```powershell
docker build -t rocketcounter:latest .
```

и уже создаем копии в количестве двух штук (можно и больше, поэкспериментируйте с числами)

```powershell
docker compose up -d --scale rocketcounter=2 # -> вот тут прописываем любое количество копий
```

На этом все, c помощью команды, к примеру

```powershell
curl -s localhost:8085 | head
```

Суть проделанной нами работы - выяснить ровно 5 вещей

**1. --link - технически неудобный вариант**. А все потому, что он плохо масштабируется и работает в одну сторону - прописывает в хосты контейнера ID получателя и открывает доступ к переменным окружения связанного контейнера

**2. Чем же build отличается от image**. И если коротко - image ''говорит'' нашему compose.yml, откуда взять образ. В нашем случае прописан как раз таки redis. А build в свою очередь собирает образ из Dockerfile, и если Dockerfile лежит рядом с compose.yml и в yml-файле написано что-то вроде

```yaml
build: .
```

то мы все делаем правильно

**3. Масштабировать сервис с публикацией фиксированного порта на одном хосте нельзя**. Причина - один порт может занять только **один** процесс. Если мы попытаемся запустить несколько - выдаст ошибку. Но это ограничение можно обойти, воспользовавшись к примеру, нашим способом с автоматическим присвоением порта, или вообще создать несколько копий и каждой из них присвоить по своему порту

**4. У _docker compose down -v_ и _docker compose down_ есть разница**. Казалось бы, один флаг _-v_, а буквально дописав его, мы стираем тома, связанные с проектом

**5. В Compose обеспечивается сетевое имя сервиса следующим образом**:
- Создаётся отдельная bridge-сеть для проекта (имя вида <каталог-проекта>_default).
- К ней подключаются все сервисы проекта.
- После чего регистрируется в встроенном DNS Docker

**Спасибо за внимание!**

## Апдейт

Дело в том, что формулировка

```markdown
"Возникнет лишь одна проблема - образа с приложением rocket-counter нет в базах Docker"
```

в ходе работы оказалась неверной. Образ существует в базах, поэтому все, что нам нужно сделать - после команды

```powershell
docker run -d --name redis redis
```

запустить команду

```powershell
docker run -d --name rocketcounter -p 8085:5000 --link redis:redis rotorocloud/rocket-counter
```

После этого мы проделали несколько действий:
- Создали заново файл docker-compose.yml

```yaml
services:
  redis:
    image: redis

  rocketcounter:
    image: rotorocloud/rocket-counter
    ports:
      - ":5000"
```
в папке /root/rocketcounter 

- Запустили команду 

```powershell
docker compose up -d
```
из папки /root/rocketcounter

Готово. Остальные действия будут те же.
